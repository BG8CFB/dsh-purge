# 红队作战手册（插件视角）

> 本文是 dsh-purge 红队侧的业务与实现基准。红队项目（side=offense）与蓝队项目（side=defense）是两个平行形态：各自建项目、各自开库、互不可见。对抗发生在现实里，插件只负责记录与记分。

## 1. 授权与基准线（Baseline）

开工前必须钉死三样东西，缺一不开工：

| 项 | 说明 | 落库位置 |
| --- | --- | --- |
| 授权范围 | CIDR / 域名 / 资产清单，允许重叠但必须显式 | engagement.scope_cidrs |
| 时间窗 | 开始与结束时间，窗口外禁止任何主动流量 | engagement.window |
| 禁止项 | 不允许打的生产系统、不允许的数据导出、不允许的持久化 | engagement.forbidden |

红队的一切动作都记在 `attack_step` 上，带 `at` 时间戳——这是后续与蓝队复盘对齐的唯一时钟。

## 2. 主智能体（指挥）

主会话只做四件事：**计划、派活、研判回报、向用户汇报**。不自己扫、不自己打。

- 派发走 `subagent`，一次一个角色，最多 3 个并发（`redteam_agent_slot` 闸门）。
- 每次派活必须带：目标、授权范围复核、期望产物、停止条件。
- 子智能体是叶子节点（maxDepth=1），不允许再往下派。

## 3. 五个执行角色

| 角色 | 职责 | 主要产出 |
| --- | --- | --- |
| recon 信息收集 | 子域、端口、指纹、旁站、供应商 | asset / fingerprint / segment |
| assess 资产梳理 | 给资产排优先级（先打谁） | asset.priority / test_status |
| vuln-scan 漏洞发现 | 指纹匹配 POC、验证、去重 | vuln（candidate/confirmed） |
| exploit 漏洞利用 | 拿权限、WebShell、隧道、凭据 | access / webshell / tunnel / credential |
| internal 内网渗透 | 隧道横向、提权、打集权系统 | 内网资产 + 更高权限 + 得分 |

角色之间靠数据库交接，不靠对话：上一个角色必须把状态写回 `asset.test_status` 与 `vuln`，否则算没干。

## 4. 攻击链与 ATT&CK 映射

插件沿用五段阶段：`recon → internet → boundary → internal → target`。与 ATT&CK 的对应关系：

```
recon      T1595 主动扫描 / T1590 收集网络信息
internet   T1190 面向公网应用利用 / T1133 外部远程服务
boundary   T1078 有效账号 / T1566 钓鱼（演练通常禁用）
internal   T1021 远程服务 / T1570 横向工具转移 / T1068 提权
target     T1005 本地数据收集 / T1486 影响完整性（演练通常禁用）
```

每一步都要能回答三个问题：**在哪台资产上、用什么命令、拿到什么回显**。缺一个都不算得分。

## 5. 与蓝队交战（红队视角）

红队面对的不是空气，是有 EDR/WAF/IDS/蜜罐的防守方。真实的对抗动作按这个顺序：

1. **侦察阶段控速**：全端口扫描会触发流量告警，先小范围、低速率、分布式。
2. **指纹与规避**：识别 WAF/EDR 指纹后再选武器，不硬打。
3. **被拦就换路**：同一目标换协议（HTTP→DNS/ICMP 隧道）、换入口（旁站/供应商/VPN）、换身份（凭据复用）。
4. **落地即清痕**：马要改名、改默认密码、改特征；这既是隐蔽，也是避免被蓝队反制抓到。
5. **被溯源就撤**：发现对方在反制（蜜罐回连异常、命令回显延迟、IP 被反查），立即停止该路径并换资产。

红队的隐身不是目的，**在不被发现的前提下拿分**才是目的。被发现一次不扣分，但被发现后仍硬打会拖垮时间窗。

## 6. 积分规则（摘要）

25 条规则分两大类：一、获取权限（21 条）；二、突破网络边界（4 条），另有 G1–G8 通用规则。

| 规则族 | 示例 | 口径 |
| --- | --- | --- |
| 主机权限 | server-user 10 / server-admin 50 | 同一主机取最高权限一次 |
| 数据库 | db-credential | 同一实例一次 |
| Web 系统 | web-app（管理员 100 / 普通 50） | 同一系统最高一次 |
| 集权系统 | central-system（域控/堡垒机/运维平台） | 管理员档 500 |
| 边界突破 | boundary-logical 1000 / strong 10000 / physical 30000 | 整个目标一次 |
| 数据规模 | 超大数据翻倍（>1 亿条或 10TB） | 需写实际导出量 |

**每笔记分必须带 `code` + `evidence`**（目标 + 拿到什么），缺一服务端直接拒收。

## 7. 证据与报告

- 截图走 `redteam_shot_add`，HTTP 证据走 `http_evidence_add`，脚本走 `attack_file_add`。
- 报告只收录**拿到分**的成果，每条要能复现：目标 → 拿到什么 → 怎么拿到（命令）→ 原始请求。
- 收尾用 `redteam_engagement_digest` 汇总阶段、得分、缺口，再生成报告。

## 8. 知识沉淀

- 项目级 POC：本次演练专用，随项目删除。
- 全局 POC：换个目标还能用的，`scope=global` 存一份，下个项目直接命中。
- 通用化前必须脱敏：去掉目标 IP、域名、账号、内部路径。
## 9. 优化项（对照 2025 实战数据的自查清单）

参考：[2025 年 HVV 总结报告](https://cn-sec.com/archives/4358074.html)、[走过场的护网红队](http://cn-sec.com/archives/5428863.html)。

### 9.1 侦察要控速（现状：缺显式约束）

实战数据里扫描探测类 IOC 占 91%——红队一开场就会被看见。当前 recon 角色没有速率/来源约束，容易一上来全端口扫描。

- 侦察工具补 `rate` / `threads` / `source` 参数并落库；
- 先打信息泄露类（低风险、高信息量），再打代码执行类；
- 记录「这次扫描用的什么指纹」，下一轮换掉。

### 9.2 C2 隐匿（现状：只有隧道，没有 C2 基线）

Cobalt Strike 占远控 IOC 的 71%，域前置与云函数是主流隐身手段。插件有 suo5/chisel/frp/ligolo，但缺 C2 侧的检查表。

- 上线前检查：Beacon 特征、证书、域名、回连间隔；
- 记录 C2 域名/云函数地址，避免与蓝队情报库撞车；
- 备多条隧道，一条掉了立刻换。

### 9.3 云与供应链（现状：资产模型只有 IP/端口/指纹）

容器逃逸、K8s 令牌泄露、CI 投毒是近两年增长最快的入口，插件目前完全没有云侧资产类型。

- 资产类型扩展：`cloud` / `k8s` / `container` / `repo`；
- 新增工具：云凭证（AK/SK）、K8s token、镜像与依赖清单；
- 对应技战术：容器逃逸、令牌窃取、构建流水线投毒。

### 9.4 时间窗与禁止项（现状：文档有、代码没有）

`engagement.yaml` 目前只有 target/scope/status，没有 window 与 forbidden。

- 加 `window`（起止时间）与 `forbidden`（禁打系统、禁导数据、禁持久化）；
- 工具执行前校验，窗口外直接拒；
- 违规动作不记分并留痕。

### 9.5 证据可复现（现状：有 evidence，缺 repro）

记分强制 code+evidence，但报告里的「怎么拿到」靠模型自觉。整改清单要能验证，红队侧就要先能复现。

- 记分时补 `repro`（命令原文 / 原始请求）；
- 报告自动带复现步骤；
- 增加「证据完整性」自检：目标、命令、回显三缺一即警告。

### 9.6 失败路径也要记录（现状：只收得分项）

报告只收录拿到分的成果，被拦下的尝试全部丢弃——这恰恰是紫队复盘最需要的输入。

- `attack_step` 允许 `result=blocked|failed`，并记录被什么拦（WAF/EDR/人工）；
- 报告附「未遂清单」；
- 与蓝队对账时，这才是「蓝队到底拦没拦住」的证据。

### 9.7 反溯源自检（现状：无）

被蓝队反查 IP/域名/VPS 是真实风险。

- 上线前自检：VPS/域名是否在公开情报库、跳板是否暴露真实归属；
- 记录跳板链与更换时间；
- 发现被标记立即停用该路径。

### 9.8 节奏与提示（UX）

- 会话头徽章显示「阶段 + 得分」，而不是只有得分；
- 面板给「下一步建议」卡片（复用 digest），减少手动追问。

### 9.9 优先级建议

| 优先级 | 项 | 理由 |
| --- | --- | --- |
| P0 | 9.4 时间窗/禁止项 | 合规底线，最容易补 |
| P0 | 9.5 repro + 证据自检 | 直接决定报告能不能用 |
| P1 | 9.6 失败路径 | 紫队复盘的输入，成本低 |
| P1 | 9.1 侦察控速 | 降低被发现的概率 |
| P2 | 9.2 C2 检查表 | 依赖技能库扩充 |
| P2 | 9.7 反溯源自检 | 依赖外部情报 |
| P3 | 9.3 云与供应链 | 需要新的资产模型与工具集 |
