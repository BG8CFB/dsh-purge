# 红蓝对账（reconcile）

## 定位
红队与蓝队是两条平行线，互相看不到对方的库。**只有复盘时**，由用户在任何一侧的面板里触发一次只读对账。

## 谁触发
用户。模型没有对账工具（避免在蓝队会话里"看见"红队数据）。
模型能做的：
- `blueteam_reconcile_list` 读已完成的对账结果；
- 依据 verdict 写复盘结论与整改项。

## 结果怎么读
- matched：蓝队在时间窗内记录到了（delta ≤ 5 分钟）。
- late：记录到了，但超出快速响应窗口（迟报）。
- missed：完全没记录 → **漏报**，扣分。
- unverifiable：红队动作缺时间或资产标识，无法判定——不能算蓝队的锅。

## 复盘输出
1. 漏报清单 → 补日志/补规则（detection 角色）。
2. 迟报清单 → 查 SLA 与值班响应。
3. 误报与自伤清单 → 规则调优 + 审批流程改进。
4. 每条整改项带责任人与期限。
